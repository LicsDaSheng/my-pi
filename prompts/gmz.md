# gmz - 中文 Git 提交

读取当前仓库中所有已暂存（staged）的改动，分析变更内容，然后用**中文**生成一条规范的 Conventional Commits 提交信息并执行提交。

## 工作流程

1. 执行 `git status` 和 `git diff --staged` 查看所有暂存内容，同时检查是否存在未暂存（modified / untracked）的改动
2. 如果没有任何暂存内容，直接告知用户"没有已暂存的改动"，不要执行提交；同时告知用户有哪些未暂存的改动，询问是否需要一并暂存并提交
3. 分析变更的性质和范围，选择合适的提交类型
4. **如果存在未暂存的改动，必须先与用户确认**：列出这些文件，询问是否需要一并 `git add` 后再提交。得到用户明确答复前，不要擅自添加未暂存的文件，也不要直接执行提交（除非用户明确表示只提交暂存区内容）
5. 用中文撰写提交信息，格式为 `<type>: <中文描述>`
6. 执行 `git commit` 完成提交

## 提交类型

- `feat`: 新功能
- `fix`: 修复 bug
- `docs`: 文档变更
- `style`: 代码格式调整（不影响功能）
- `refactor`: 重构（非新功能、非修复）
- `perf`: 性能优化
- `test`: 测试相关
- `chore`: 构建、依赖、配置等杂项
- `ci`: CI/CD 变更

## 提交信息格式

```
<type>: <中文描述>
```

示例：
- `feat: 新增用户登录接口`
- `fix: 修复列表分页越界问题`
- `docs: 更新 README 安装说明`

要求：
- 描述使用简体中文，简洁准确，概括本次变更的核心内容
- type 保持英文小写，冒号后有一个空格
- 如果变更涉及多个方面，选取最主要的一个类型，描述中概括要点；必要时可在正文部分用列表补充细节
- 未经用户确认，**不要**执行 `git add` 添加未暂存的文件
